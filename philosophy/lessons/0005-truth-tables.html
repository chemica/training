Lesson 5 · Truth-functional logic · 20–25 minutes

Make every valuation answer

A truth table replaces “I cannot imagine an exception” with a finite search through every truth-value assignment. Learn to build that search without skipping cases, calculate a compound sentence, classify its final column, and recognise the row that refutes validity.

Your win for today

By the end, you will be able to complete a two-letter truth table and use it for three jobs: evaluating a formula, classifying it, and testing whether an argument has a countermodel.

What a complete table proves

A valuation assigns either true or false to each sentence letter. One row represents one valuation; a complete truth table contains every valuation for the letters in use. That word “complete” does the important work. Testing a few rows can reveal failure, just as one counterexample can refute a universal claim. To establish by the complete-table method that no truth-functional counterexample exists, however, you must cover every valuation. Later you can learn proof systems and truth-table shortcuts that establish the same result without writing every row.

The authors of forall x: Calgary introduce valuations with the letter B, connected by a symbolisation key to “Big Ben is in London.” Their point is that a valuation need not report the actual world: although Big Ben is in London, we may stipulate B false to examine that assignment. A truth table explores formal combinations rather than conducting empirical research. With one letter there are two rows. With two letters there are four; with three, eight. In general, n distinct letters require 2n rows. Repetition does not add rows: a formula containing A five times still has only one distinct letter. To generate rows reliably, alternate true and false in the rightmost letter’s column; move left and double the run length each time. Once the rows are present, the five connective rules do the arithmetic. Negation reverses a truth value. A conjunction is true only when both conjuncts are true. An inclusive disjunction is true when at least one disjunct is true. A biconditional is true when its two sides have the same truth value. A conditional is false only when its antecedent is true and its consequent false. These are not rules of good causal explanation or ordinary conversational relevance; they specify the behaviour of the truth-functional symbols introduced in Lesson 4. The statements are paraphrased from the textbook’s characteristic truth tables.

The conditional is the usual source of hesitation. Read A → B as ruling out exactly one combination: A without B. If A is false, that forbidden combination has not occurred, so the material conditional is true. You need not pretend that every such conditional is informative in ordinary speech. Truth-functional evaluation asks a narrower question: given these truth values, what value does this formula receive?

Calculate inward, then read outward

The textbook develops a complete table for (H ∧ I) → H. This is a good teaching formula because it forces two calculations without needless clutter. First calculate the smaller conjunction H ∧ I. Then treat that result as the antecedent of the whole conditional. The order matters: trying to evaluate the main conditional before knowing its antecedent leaves one of its inputs blank.

Why is every final value true? On the first row the antecedent and consequent are both true. On each remaining row the antecedent H ∧ I is false, so the conditional is true. A common failure is to read the last H directly from the atomic column and call that the answer. It is only the consequent. The value of the whole sentence sits under its main connective, here the arrow. Marking that column prevents a bookkeeping mistake from masquerading as a logical result.

Three questions, one table

A completed final column can answer different questions, so decide what you are testing before interpreting it. A formula is a tautology when it is true on every valuation, a contradiction when it is false on every valuation, and contingent when it is true on some valuations and false on others. Thus the worked formula (H ∧ I) → H is a tautology. These are semantic classifications inside truth-functional logic. They do not say that a contingent claim is doubtful, that a contradiction is merely controversial, or that every necessary truth can be recognised as a tautology.

The last qualification matters. The textbook uses “2 + 2 = 4” to show the boundary of the method. If that entire mathematical sentence is represented by one sentence letter, truth-functional logic permits the letter to be false; its internal mathematical necessity has disappeared from the representation. Truth tables exhaust the valuations of a formalisation, not every fact about the subject formalised. For an argument, ignore the all-true or all-false pattern and hunt for a different one: a row on which every premise is true and the conclusion is false. Such a row is a countermodel. One countermodel proves the argument invalid. If a complete table has none, the premises entail the conclusion in truth-functional logic. This is why truth-table validity is more than checking whether the actual premises and conclusion happen to be true. Validity concerns every valuation.

The textbook tests the familiar invalid pattern A → B, B ∴ A. Its decisive row assigns F to A and T to B. The conditional is true because its antecedent is false, the second premise B is true, and the conclusion A is false. Nothing else is needed: this one row is the countermodel.

P1A → B P2B CA ROWA = F; B = T. Both premises are true and the conclusion is false.

The usual mistake is to find a row with a false conclusion and stop. That is not enough: at least one premise may also be false. Another mistake is to treat a countermodel as a claim about what actually happened. The assignment need only demonstrate that the premises’ truth does not force the conclusion’s truth. When you return to a real argument, translate the formal possibility into an intelligible scenario and then ask whether the original symbolisation captured the prose fairly.

Keep the method compact

On paper, identify the distinct letters; generate all 2n valuations; calculate the smallest subformulas before larger ones; mark the main-connective columns; and interpret those columns for the question asked. For classification, inspect the whole final column. For validity, scan for the forbidden true-premises-and-false-conclusion row. If you find one, stop: invalidity is established. If you find none, make sure the table really was complete before declaring the inference valid.

Truth tables earn their authority through exhaustion. Build every valuation, calculate from the inside out, and let the relevant column—not the plausibility of the conclusion—settle the formal question.
