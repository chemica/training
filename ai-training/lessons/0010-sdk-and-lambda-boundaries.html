Lesson 0010 · DVA-C02 development

Call AWS deliberately.

Learn SDK clients, credentials, Regions, Lambda events and contexts, configuration, retries, and the boundary between your code and a managed service.

45–60 minutes · AWS Certified Developer – Associate

1 · Orient

Prerequisite: request, resource, Region, principal, role, policy, temporary credential, log, metric, and timeout.

Outcome: You can design a Lambda handler that receives an event, validates input, calls an AWS service through an SDK, and returns controlled errors without embedding credentials.

Theme · Why service boundaries deserve explicit code

Moving code into Lambda does not remove application architecture; it makes boundaries more important. The handler receives an event from one system, validates it, invokes application logic, and translates the result into the caller's expected response. AWS SDK calls then cross another boundary where identity, timeouts, throttling, and service errors apply.

In our document-intake API, parsing HTTP input, deciding business behaviour, and storing state should not collapse into one opaque handler. Separating them makes the logic testable without AWS and makes failures attributable to the correct owner.

Configuration belongs outside source code, credentials come from the execution role, and errors are translated deliberately rather than leaked to the client.

2 · Learn the development interfaces

AWS Management Console
A browser interface for people to inspect and manage AWS.
AWS CLI
A command-line client for AWS service APIs.
AWS SDK
A language library that constructs, signs, sends, retries, and parses AWS API requests.
API operation
A named action offered by a service, such as putting an S3 object or invoking a model.

The console, CLI, and SDK call service APIs. They do not bypass authorization. The caller needs credentials and permission for the requested action and resource.

3 · Learn Lambda inputs

A Lambda handler is the configured function entry point. The event contains invocation data. The context contains runtime information, including the invocation request ID and remaining execution time.

Environment variables provide configuration such as table names or feature flags. They are not a safe default for plaintext secrets. Use a managed secret service and a workload role where appropriate.

A Lambda execution environment can be reused. Code outside the handler can initialize an SDK client once per environment, reducing repeated setup. Your code must not depend on reuse occurring.

4 · Learn error ownership

Validate untrusted input at the application boundary. Separate client errors from dependency failures and internal defects. A retry can help with a transient throttle or service fault. It does not fix invalid input or missing authorization.

SDKs can perform automatic retries. Application retries layered on SDK retries can multiply requests and cost. Use bounded attempts, backoff, and idempotent operations where possible.

Worked example

import boto3
import os

bedrock = boto3.client("bedrock-runtime")
MODEL_ID = os.environ["MODEL_ID"]

def handler(event, context):
    text = event.get("text", "").strip()
    if not text:
        return {"statusCode": 400, "body": "text is required"}

    # The SDK gets temporary credentials from the Lambda execution role.
    # A later lesson implements the model request and structured logging.
    return {"statusCode": 202, "body": context.aws_request_id}

The model ID is configuration. Credentials are not in the source or environment variable. The SDK obtains temporary credentials supplied for the execution role. The request ID provides correlation evidence.
