Lesson 0004 · Identity and cost safety

Secure before you build.

Learn the account, identity, permission, audit, and cost-control terms required before you create AWS resources.

40–55 minutes · AIF-C01 governance and DVA-C02 security

1 · Orient

Prerequisite: principal, authentication, authorization, role, policy, and shared responsibility.

Outcome: You can explain a safe learning-account baseline and distinguish an IAM identity from a cost-management control.

No console task yet. This lesson teaches the controls. Account creation and configuration will use a separate guided procedure.

Theme · Why the account is part of the system

An AWS account is not merely a login for reaching some tools. It is a security, billing, and resource boundary. A mistake in identity configuration can expose data; a forgotten resource can continue generating cost; and an absent audit trail can make an incident impossible to reconstruct.

Our learning account will host APIs, queues, documents, and model calls. MFA strengthens proof of identity, IAM policies decide allowed actions, CloudTrail records API activity, and Budgets warn about spending. None substitutes for another.

This lesson builds the habit of connecting each control to a named risk—essential when a customer asks why they should trust an application you built.

2 · Learn account identities

AWS account
A security, billing, and resource-isolation boundary. Resources and identities are owned or governed through accounts.
Root user
The identity created with the account email address. It has complete account access and some tasks only it can perform. Protect it with MFA and do not use it for daily work.
IAM user
A long-lived identity inside one account. Prefer federation or temporary credentials for human access where practical.
Federation
Trusting an external identity system so a person can sign in and assume an AWS role without a separate long-lived AWS password.
Multi-factor authentication
Authentication that requires an additional factor beyond a password.

3 · Learn policy evaluation

A policy statement commonly contains an Effect, Action, Resource, and optional Condition. An identity-based policy is attached to an identity. A resource-based policy is attached to a resource.

A request is denied by default. An applicable allow can permit it. An applicable explicit deny overrides an allow. Other controls can further restrict the result. This is why “the role has AdministratorAccess” is neither a diagnosis nor a safe fix.

4 · Learn audit and cost controls

CloudTrail
Records AWS API activity for audit and investigation.
Tag
A key-value label attached to a resource for organization, automation, and cost allocation.
AWS Budget
A cost or usage threshold with notifications and optional actions. A notification is not the same as a guaranteed hard spending cap.
Cost Explorer
A tool for viewing and analysing historical and forecast AWS cost and usage.
Free Tier
Service-specific free usage or temporary credits subject to eligibility and limits. It does not make all AWS activity free.

Worked example

A learner protects the root user with MFA and stores its recovery information safely. Daily access uses a federated administrator role initially, then narrower workload roles. Every lab resource receives Project, Environment, Owner, and DeleteAfter tags.

Budget notifications are set at $5, $15, and $30. CloudTrail provides audit evidence. The learner checks Cost Explorer after labs and destroys resources with hourly idle charges. The budget warns; cleanup prevents.

6 · Apply it

Write a safe-account checklist under four headings: root identity, daily identity, audit evidence, and cost response. For each item, state the risk it controls. Do not create the account yet.
