Lesson 0012 · DVA-C02 delivery and operations

Make the system repeatable.

Learn infrastructure as code, stacks, environments, CI/CD, deployment strategies, rollback, structured telemetry, alarms, and runbooks.

55–75 minutes · AWS Certified Developer – Associate

1 · Orient

Prerequisite: resources, IAM roles, Lambda, API Gateway, S3, SQS, DynamoDB, logs, metrics, traces, and request IDs.

Outcome: You can specify a repeatable delivery path and the minimum evidence needed to operate the first portfolio application.

Theme · Why deployability is part of the product

An application that works only in its author's AWS account is a demonstration, not a dependable product. Infrastructure as code records the desired resources and configuration so an environment can be reviewed and rebuilt. A delivery pipeline applies changes consistently and stops when checks fail.

Deployment is only half the responsibility. Logs explain discrete events, metrics reveal behaviour over time, and traces connect work across service boundaries. Alarms turn selected measurements into action, while a runbook tells an operator what to inspect and how to recover.

The first portfolio repository reaches its release gate when another developer can deploy it, observe it, diagnose a rehearsed failure, and remove it without relying on undocumented knowledge.

2 · Learn repeatable infrastructure

Infrastructure as code (IaC) defines infrastructure in version-controlled files. AWS CloudFormation deploys a set of related resources as a stack. AWS SAM adds serverless-focused syntax and tooling and transforms templates into CloudFormation resources.

An environment is an isolated deployment context such as development, test, or production. Configuration values differ by environment; architecture rules and source history should remain controlled.

Configuration drift occurs when deployed resource configuration differs from its declared or expected state. Manual console edits create hidden differences and weak review evidence.

3 · Learn delivery terminology

Continuous integration (CI)
Frequently combining changes with automated build, test, and validation.
Continuous delivery (CD)
Keeping validated changes in a deployable state through an automated delivery process.
Artifact
A versioned output supplied to deployment, such as a code package or container image.
Version
An immutable published Lambda function snapshot.
Alias
A named pointer to a Lambda version that can support controlled traffic shifting.
Rollback
Restoring a known acceptable version or configuration after a failed change.

A deployment strategy controls how traffic moves to a new version. All-at-once is fast but exposes all traffic immediately. Canary or linear shifting exposes part of the traffic first, giving alarms time to stop and roll back.

4 · Learn operational evidence

A structured log uses consistent named fields rather than free-form text. A correlation ID connects events for one logical operation across services. A metric measures behavior over time. An alarm evaluates a metric against a threshold and state.

A dashboard presents selected operational signals. A runbook gives an operator concrete diagnosis, mitigation, verification, and escalation steps. A dashboard without an action path only displays anxiety.

Useful service metrics are not sufficient on their own. Add business and application measures such as successful summaries, invalid-output rate, end-to-end latency, queue age, DLQ depth, token use, and cost per successful task.

Worked example

A pull request runs template validation, unit tests, integration tests, dependency checks, and an evaluation smoke set. Merge produces a versioned artifact. SAM deploys it to a test stack, tests run against the endpoint, and an approval promotes the same artifact.

A Lambda version receives 10% canary traffic through an alias. Alarms watch error rate, p95 latency, and successful-task rate. A failing alarm stops deployment and shifts traffic back. Logs contain timestamp, severity, operation, request ID, correlation ID, result, duration, and safe error code. The runbook tells the operator how to find the deployment, inspect evidence, roll back, and verify recovery.
