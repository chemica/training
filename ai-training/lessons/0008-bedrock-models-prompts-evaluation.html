Lesson 0008 · AIF-C01 domain 3

Choose with evidence.

Learn Bedrock model access, prompt techniques, inference controls, guardrails, and evaluation design before making a model choice.

45–60 minutes · AWS Certified AI Practitioner

1 · Orient

Prerequisite: foundation model, token, context window, inference, temperature, responsible-AI control.

Outcome: You can define a small evaluation, compare candidate models, and separate prompt controls from Bedrock Guardrails.

Theme · Why model choice is an engineering decision

Amazon Bedrock gives an application a managed route to several foundation models, but access to more models does not tell us which one belongs in a product. A model must be judged against the task, the risk, latency, throughput, context needs, and cost—not against an impressive conversation in a playground.

For the support copilot, we first define representative tickets and expected properties of good output. Prompt techniques provide the model with instructions and examples. Guardrails can help block specified content, but they do not establish factual correctness. Repeatable evaluation compares candidates and catches regressions when the prompt or model changes.

The result is a model-selection record backed by evidence, not preference.

2 · Learn the Bedrock boundary

Amazon Bedrock is a managed service for building generative-AI applications with supported foundation models and related capabilities. On-demand inference charges for use without reserved model capacity. Provisioned Throughput reserves model capacity for a commitment and is not the default for learning projects.

A model's availability varies by Region and inference profile. A model name alone is not a deployable architecture decision. Confirm availability, data-residency implications, quotas, price, modality, context size, and API support.

3 · Learn prompt techniques

System instruction
High-level behavior and boundaries supplied to the model.
Zero-shot prompt
An instruction without task examples.
Few-shot prompt
An instruction with a small set of input-output examples.
Prompt template
A versioned structure with controlled variables inserted at runtime.
Structured output
Output constrained to a machine-readable shape, such as a validated JSON schema.

Prompt text is application code and should be versioned, reviewed, tested, and rolled back. Temperature changes variability. It does not replace validation or evidence.

4 · Learn guardrails and evaluation

A guardrail applies configured safety and policy controls to inputs or outputs. It can help filter categories or sensitive information. It does not prove correctness, authorization, or fitness for a business purpose.

An evaluation dataset is a fixed set of representative inputs with expected properties. A rubric defines how outputs are judged. Useful dimensions include correctness, groundedness, relevance, completeness, format validity, harmful content, latency, and cost.

A baseline is the result from a simple current approach. A new prompt or model must beat the baseline on the dimensions that matter, not only produce one impressive answer.

Worked example

A ticket classifier must return category, urgency, and a short reason as JSON. The team creates 40 representative tickets, including ambiguous and unsafe inputs. The baseline is a rule-based classifier.

Two Bedrock models receive the same versioned prompt and output schema. The evaluation records classification accuracy, schema-valid rate, unsafe-output rate, p95 latency, and estimated cost. A few-shot prompt is retained only if the measured gain justifies its extra tokens. A guardrail handles configured content classes, while application validation rejects invalid JSON.
