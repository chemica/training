Lesson 0006 · AIF-C01 domain 2

Understand the model call.

Learn foundation models, large language models, tokens, context windows, embeddings, inference parameters, and adaptation methods.

40–50 minutes · AWS Certified AI Practitioner

1 · Orient

Prerequisite: model, training, inference, feature, and evaluation metric.

Outcome: You can explain what enters and leaves a text-model request, what the context window limits, and when prompting, RAG, or fine-tuning changes a solution.

Theme · Why generative applications need a different mental model

A conventional function should return a predictable result for a given input. A generative model produces a likely continuation from patterns learned during training. Its output can be fluent without being correct. Application code must therefore supply context, constrain the task, validate outputs, and decide what evidence is required.

Our support copilot sends instructions and ticket text as tokens within a limited context window. The model performs inference and generates an answer token by token. Temperature can alter variation, but it cannot add missing knowledge or guarantee truth. Embeddings solve a different problem by representing meaning numerically for retrieval.

These distinctions let us choose intelligently between prompting, retrieval-augmented generation, and model adaptation.

2 · Learn model terminology

Generative AI produces new content such as text, images, audio, video, or code. A foundation model is trained on broad data and can support many downstream tasks. A large language model (LLM) is a foundation model focused on language.

A model parameter is a learned internal value. More parameters do not guarantee that one model is better for a particular task. Evaluation must include quality, latency, price, context size, modality, safety, and regional availability.

3 · Learn input and representation

Token
A unit of text processed by a model. A token is not reliably equal to one word or one character.
Context window
The maximum token capacity available to the model for the input and generated output under the model's rules.
Embedding
A numeric vector that represents semantic properties of data. Similar meanings can be near each other in vector space.
Multimodal model
A model that accepts or produces more than one modality, such as text and images.

Adding text to a prompt consumes context. Conversation history, retrieved passages, instructions, tool results, and generated output all compete for limited capacity.

4 · Learn generation controls

An inference parameter controls generation without retraining the model. Temperature influences randomness in token selection. A lower value often gives more repeatable output; it does not guarantee factual accuracy. A maximum-output setting limits generated length and cost.

Prompt engineering changes instructions and examples supplied at inference time. Retrieval-augmented generation (RAG) retrieves external information and includes it as context. Fine-tuning changes model behavior by additional training on task-specific examples. These solve different problems.

Worked example

A support-answer service needs current policy facts and citations. Prompt engineering can define tone and output format. RAG can provide current approved policy passages. Fine-tuning is not the first choice for frequently changing facts because the training process does not provide a simple, auditable document lookup.

The request contains system instructions, the user question, retrieved passages, and formatting rules. The response consumes output tokens. The team measures answer groundedness, latency, and cost rather than assuming a larger model is best.
