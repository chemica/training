Lesson 0002 · Learn, then test

Trace one request.

Learn the AWS terms for a request path. Then use those terms to explain identity, failure, and diagnostic evidence.

About 30–40 minutes · No AWS account required · Supports DVA-C02 security and troubleshooting

1 · Orient

Prerequisite: You know what an HTTP request, API, function, and log are in general software development. This lesson teaches the AWS-specific names and boundaries.

Outcome: You can trace a serverless request and explain which identity makes each call, one plausible failure, and the evidence you would inspect.

Sequence: Sections 2–4 teach the material. Section 5 is the first knowledge check. Section 6 is the application task.

2 · Learn the system terms

An AWS service is a capability that AWS provides. Examples include AWS Lambda and Amazon S3. A resource is one configured instance of a service. One Lambda function and one S3 bucket are resources.

A client is software that sends a request. A request asks another component to do something. A response reports the result.

Client → Amazon API Gateway → AWS Lambda → Amazon Bedrock

Amazon API Gateway

API Gateway provides an HTTP API boundary. It receives the public request. It can validate parts of the request, apply access controls, limit request rates, and route an accepted request to a backend.

AWS Lambda

Lambda runs application code in response to an invocation, which is a request to run the function, or an event, which is a record that something occurred. You provide the code and configuration. AWS manages the underlying compute infrastructure. A configured Lambda function is a resource.

Amazon Bedrock

A foundation model is a large model trained on broad data that can be adapted to many tasks. Inference is the use of a trained model to produce an output from an input. Bedrock gives an application controlled access to foundation models and related generative-AI capabilities. In this path, Lambda sends an inference request to Bedrock and receives a model response.

Amazon S3 and Amazon SQS

S3 is object storage. An object contains data and metadata inside an S3 bucket. SQS is a message queue. A producer sends a message; a consumer receives and processes it.

A synchronous call makes the caller wait for completion. An asynchronous flow lets the caller submit work without waiting for all processing to finish. SQS is useful when slow work should continue separately from the original HTTP request.

3 · Learn identity and permission terms

A principal is an identity that can make an AWS request. A principal can represent a person, application, or AWS service.

Authentication verifies which principal made the request. Authorization decides whether that principal can perform a specified action on a specified resource.

Authentication: “Which principal is this?”

Authorization: “Can this principal perform this action on this resource?”

An IAM role is an AWS identity with a set of permissions. An approved principal assumes the role and receives temporary credentials. Lambda uses an execution role when its code calls another AWS service.

An IAM policy is a JSON document that defines allowed or denied actions, resources, and optional conditions. Least privilege means granting only the permissions required for the task.

Identity on the main path

  • The client presents a user or application identity to API Gateway.
  • API Gateway is permitted to invoke the selected Lambda function.
  • The Lambda function uses temporary credentials from its execution role.
  • The execution role permits only the required Bedrock actions and models.

The browser must not receive the Lambda execution role. Browser code is controlled by the user. A user can inspect it, change it, and send requests that bypass the interface. The server-side function is the controlled boundary for validation, authorization, model choice, usage limits, and logging.

4 · Learn failure and evidence terms

A failure mode is one specific way that a component or interaction can fail. “It breaks” is not useful. “The Lambda execution role does not permit bedrock:InvokeModel” is useful.

Evidence is recorded information that helps you confirm or reject an explanation for a failure.

Log
A timestamped event record with diagnostic details.
Metric
A numeric measurement recorded over time, such as error count or latency.
Trace
A connected record of one request across multiple components.
CloudTrail event
An audit record of an AWS API action. It helps answer who did what, when, and against which resource.
Request ID
An identifier used to connect evidence about one request.

Observability is the ability to understand a system's state and behavior from its outputs. Logs, metrics, and traces are observability signals. CloudWatch stores and presents many operational signals. CloudTrail focuses on AWS API audit activity.

Two common operational failures are a timeout, when work exceeds an allowed duration, and a throttle, when a service temporarily rejects work because a rate or capacity limit was exceeded.

Worked example

The client sends POST /summaries. API Gateway accepts the HTTP request and invokes Lambda. Lambda validates the input and calls a Bedrock model.

Arrow: Lambda → Bedrock

Identity: The Lambda execution role is the AWS principal. Lambda obtains temporary credentials for this role.

Authorization: An IAM policy must allow the required Bedrock inference action for the permitted model resource.

Failure mode: The policy does not permit the action. Bedrock returns an access-denied error.

Evidence: The Lambda log contains the error and request ID. A CloudTrail event records the attempted AWS API action. CloudWatch metrics show the Lambda invocation as an application error if the code reports it correctly.

Worked asynchronous example

A user uploads a document for later processing:

  1. The client uploads an object to a controlled S3 location.
  2. An event causes an ingestion message to enter SQS.
  3. A Lambda consumer receives the message.
  4. The consumer processes the document and records the result.
  5. The client checks status through a separate request.

The original client does not wait for all processing. The queue also absorbs bursts. Later lessons will teach retries, idempotency, visibility timeouts, and dead-letter queues before they are assessed.

5 · Retrieve what you learned

Now close or cover Sections 2–4. This check uses only terms explained above.

6 · Apply it

Redraw this path from memory:

Client → API Gateway → Lambda → Bedrock

For each arrow, write:

  1. Identity: Name the principal that makes the request.
  2. Failure: State one specific failure mode.
  3. Evidence: Name the log, metric, trace, CloudTrail event, response code, or request ID that would help diagnose it.

Finally, answer: Why should Lambda invoke Bedrock instead of giving the browser direct Bedrock permission?

7 · Review

Send your annotated path and final answer to your teacher. Feedback will check terminology and reasoning. It will not require concepts that this lesson did not teach.
